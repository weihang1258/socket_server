## 三、复测新问题（N1-N7）处理说明

| 项 | 定性 | 处理 |
|---|---|---|
| **N1** boce error 计 ok:1 | 属实，采纳 | `client.boce_run` 补 error 判定：服务端 131 前置失败返回 `{"error":...}` 时判失败抛错（reason 含原文），不再计 ok。测试 `test_boce_error_failed` |
| **N2** 弹窗/未知模式失败表现为"连接关闭" | 属实（呈现层） | 根因是服务端 131 分支 boce() 异常冒泡到协议层断连。已修（1.7.2）：131 分支异常捕获，转 `{"error": "拨测失败: ..."}` JSON（与正常响应同型）。测试方"建议 131 分支捕获异常并返回 error JSON"已照做 |
| **N3** capture_start 失败文案不携带原因 | 属实（根因在服务端） | 服务端 1.7.2：`tcpdump_start` 四个失败分支记录原因到 `_last_start_error`，dt5 失败响应带 `{"res":false,"error":"..."}`（如"路径不可写""无默认路由""子进程启动超时"）；桥层 0.2.3 经 `_error` 通道透传到 reason。**已在 82 机（1.7.2）实测**：不存在目录 → reason=`[Errno 2] No such file or directory: ...` |
| **N4** socket_listen 重复 stop 报错原始 bytes | 属实，采纳 | 同 B09：`_decode_listen_error` 覆盖 stop 分支 |
| **N5** serverInfo.version=1.28.1 | 属实（框架限制） | FastMCP 1.28 签名无 version 参数（已核实源码），构造后直设底层 `Server.version`。0.2.4 起initialize 返回 serverInfo 0.2.4（已实测）；另 `__init__.py` 0.1.0 → 同步 0.2.4 |
| **N6** boce timeout 改名破坏旧调用 | 属实，已按新方案回归 | **0.2.4 恢复单 `timeout` 参数**：一个参数两层语义——既约束单靶机整体操作，拨测内部 HTTP/goto 预算取同值扣 10s 余量（0.2.1 的"拆 http_timeout"方案废弃，0.2.2 的"单参数但内层=外层"方案修正为"内层自动扣余量"）。旧调用 `{"timeout": 3}` 语义恢复。另加 schema 下限 `ge=10`（低于 10 秒会使内层预算≥外层，必然超时，pydantic 校验直接拒绝并给出明确错误） |
| **N7** 每次弹窗失败新增 chrome 僵尸 | 属实（缓解措施已加） | 根因：browser 崩溃后残留 chrome 子进程无人回收（`kill_all_chrome` 无调用点）。已修（1.7.2）：浏览器类拨测异常路径自动调用 `kill_all_chrome()` 清理。彻底根治需 prctl(PDEATHSIG) 或 waitpid 回收线程，已记录待办（服务端项，随下批） |
