## 二、本轮修复明细

### N7 chrome 僵尸（1.7.3 修复，需复测）
**根因**：chrome 由 pyppeteer 在 agent 进程内经 subprocess 拉起，browser 崩溃后 chrome 死亡，父进程未 waitpid → `<defunct>`。僵尸已死，`pkill` 杀不动，只能由父进程 waitpid 回收。
**修复**（boce.py）：新增收割线程——`os.waitpid(-1, os.WNOHANG)` 5 秒轮询（daemon），对所有已退出子进程（chrome/抓包残留等）统一回收；幂等启动。已验证：本机直调测试中子进程退出后被收割线程收走。
**重测**：35 机连续 3 次弹窗拨测失败 → `ps -eo stat,comm | grep "^Z"` 断言 chrome 僵尸数无净增。

### N6 boce timeout（0.2.4 已按裁定回归，0.2.5 保持）
当前语义（描述已更正为真实行为）：**`timeout` 单参数两层语义**——工具总超时（socket 层 = timeout+10s 余量，给 browser 冷启动/判定收尾留窗口），内部 HTTP/goto 预算 = timeout−10（至少 3s）；**下限 10 秒**（ge=10），低于 10 秒的调用被 pydantic 校验拒绝并报"Input should be greater than or equal to 10"。
**说明**：补充函第六节"旧式传 {"timeout": 3} 即拨测 HTTP 超时 3 秒——语义已恢复"表述错误，正确表述为"**timeout ≥10 的旧值语义兼容（作为拨测预算）；<10 将被参数校验拒绝**"。已按此更正工具描述。

### N2 附条件（timed out 掩盖内层失败）—— 0.2.5 修复，需复测
**根因**：内层预算（goto 3s）只约束 goto 一段，run_single 全程（browser 冷启动 5-8s + goto + 判定收尾）无预算上限；外层 socket timeout（=timeout）先到 → 内层结构化失败被 timed out 掩盖。
**修复**：boce_run 的 socket 层超时改为 **`timeout + 10` 余量**（外层比调用方业务预算大 10 秒），保证内层结构化失败先于外层超时返回。实测 spy 断言：timeout=10 → socket_timeout=20。
**重测**：timeout=10 + 弹窗失败场景 → 应返回 `{"ok":0,"failed":[{"reason":"boce failed: ..."}]}` 而非 timed out。
